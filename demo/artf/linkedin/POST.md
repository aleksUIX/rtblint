IAB Tech Lab published #ARTF, the Agentic Real Time Framework, so an agent can take part in an auction from inside the host that is already running it. That host is an SSP, a DSP, or an exchange. It deploys the agent as a container in its own infrastructure and calls it while the bid is still moving. The agent never gets a copy of the data to take elsewhere, and the host keeps control of timing and of which changes actually land. The practical upside is that you can package the agent once and run it on any platform that follows the spec. The working group’s examples are the jobs that have always been tight on time: identity, turning deals and segments on, catching fraud before the impression.

None of this introduces a new ad object. The BidRequest is still OpenRTB: impressions, deals, segments, in the same language every SSP and DSP already speaks. The agent proposes a patch and the orchestrator decides, change by change, what to apply. Buyers then bid on whatever the host actually forwarded. The same hop can run again after a bid comes back, this time on the BidResponse. What does not stay automatic is correctness. A well-formed call can still write a string where OpenRTB wants a number, or point at an impression this auction does not have. If several writers share one language, the host needs a deterministic check that the object is still valid OpenRTB after those patches, and that check has to be fast enough to run before the request goes out.

What ARTF does not cover is everything after a winner is chosen. The creative still goes out as VAST or DAAST, the player still renders it, and measurement still fires. That part of the stack is unchanged.
