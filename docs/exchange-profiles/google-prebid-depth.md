# Google Authorized Buyers and Prebid Server depth

Reviewed on 2026-10-09. Google uses the fetched protocol v210 downloads. PBS-Go uses commit `fa73b89049767eaab6d9f48dc3b0a275db563233`. [Source URLs and byte hashes](google-prebid-sources.json), the [Google descriptor inventory](google-prebid-google-wire-inventory.json), and [replayable cases](../../fixtures/exchange-depth/google-prebid/cases.json) preserve the evidence.

Google JSON extension checks cover all 21 extension roots, 63 reachable messages and 246 known field shapes declared in the downloaded protocol. They enforce array/member shapes, nested messages, numeric enums, 32-bit integer bounds, 64-bit decimal strings, integer boolean flags and protobuf oneofs. Unknown future extension keys stay open. Native request extensions and decoded native response event trackers have explicit hooks. The descriptor is generated before release, with no protobuf build or runtime dependency.

The profile also checks Google landing-page declarations, frequency-cap syntax and limits, DSA payer and declaration lengths. Paired checks cover multiple-ID billing attribution, deal billing/media eligibility, SDK identifier offers, exact SDK parameter-set selection, collapsible banner bounds and an explicit unsupported frequency-cap scope. A supplied billing ID outside a sole offered ID is a warning because Google can ignore it when no child seats are active. Unknown account settings cannot establish that exception. Malformed or ambiguous reference lists defer comparisons. Null does not select a billing ID and still receives the existing wire-type diagnostic.

The [current Buyer SDK guide](https://developers.google.com/authorized-buyers/rtb/buyer-sdk-ads) requires adomain, billing ID, creative ID, dimensions, SDK ID, rendering data and a declared creative when `sdk_rendered_ad` is selected. These conditions stay within that selected context. Selecting a separate ordinary or AMP creative alongside an SDK creative is invalid. Declared SDK Native image assets require image type, while their IDs need not match requested assets. Provided Native link, title, image, video and data objects retain their published protocol member requirements. Parameter comparison accepts reordering and exactly one complete offered mapping. Missing or empty parameter selection does not establish a chosen mapping. Partial, malformed or duplicate-key references defer. Notification-token payloads whose parsed string exceeds 128 UTF-8 bytes produce an ignored-token warning. They are string fields, so the limit does not count JSON escapes or decode opaque base64-looking strings. These rules come from the pinned protocol and the independently retrieved SDK guide. The [SDK fixture generator](google-sdk-case-generate.py) supplies required surrounding context without replacing descriptor mutation fields.

Google's documented legacy extension locations remain valid under its declared profile. The default spec still reports moved paths. The source guide describes Google's OpenRTB JSON encoding, including integer extension flags. This does not certify the separate IAB ProtoJSON dialect or binary protobuf messages. [Google integration guide](https://developers.google.com/authorized-buyers/rtb/openrtb-guide), [multiple-account billing](https://developers.google.com/authorized-buyers/rtb/response-guide/bid-multiple), and [frequency-cap limits](https://support.google.com/authorizedbuyers/answer/10890762?hl=en) explain these requirements.

PBS checks deepen stored IDs and entries, channel strings, strict JSON booleans, aliases/GVL IDs, custom currency-rate wire shapes, targeting, custom and legacy price granularities, cache selectors, SDK renderer shapes, buyer UID maps, reward flags and response extensions. Bid media markers must agree with a known `mtype`. Paired media offers are checked only when stored request expansion cannot supply missing media.

The public auction documentation and pinned Go implementation distinguish invalid wire shapes from normalized settings. Multibid omissions, clamping, duplicate selectors and ignored grouped prefixes produce warnings, matching the implementation's recoverable outcomes. Multiple requested currencies produce a warning for PBS-Go's first-currency behavior. Missing price precision accepts the documented default; supplied precision follows the reviewed Go bound of 15. Go accepts the legacy `medium` alias in addition to the documented legacy names.

Stored request content is unavailable locally. It can fill bidder configuration, cache selection, aliases and media. The raw profile does not prove those merged fields missing. JSON arrays that replace a stored array still need complete observed entries. Bidder registration, enabled adapters, publisher accounts, consent actions, cache success, currency conversions, floors and runtime targeting results remain outside this static evidence. [PBS auction contract](https://docs.prebid.org/prebid-server/endpoints/openrtb2/pbs-endpoint-auction.html) and the pinned implementation links in the source manifest distinguish common request fields from Go behavior. Java-only and host-specific behavior is not certified.

The corpus includes positive and mutation controls for all 246 distinct Google descriptor fields, plus independent SDK, token and paired context boundaries. These counts describe fixtures and wire-field boundaries, not a percentage of exchange acceptance or complete behavioral specification coverage. The [verification receipt](google-prebid-verification.json) records final counts. Run `cargo test -p rtblint-core --test exchange_depth_google_prebid` to replay them.

Remaining Google semantic gaps include SKAdNetwork cryptographic signatures, creative restrictions that require remote classification, frequency counters, confidential child-seat configuration, account currencies, third-party token provenance, publisher-managed creative handling and rendering. SDK creative-review approval and rendering-data equivalence require external evidence. Remaining PBS gaps include adapter-specific parameter schemas, deployment bidder aliases, stored-request resolution, host settings, Java-only extensions and external cache/privacy behavior. Descriptor shapes do not prove these outcomes.
