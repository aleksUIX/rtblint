ARTF (IAB Tech Lab Agentic Real Time Framework) lets a host (SSP, exchange, DSP) run a container beside the auction and accept mutations to the OpenRTB payload already on the wire. The host applies whichever it accepts. The framework does not ask whether the result is still a legal auction.

1. Where it sits

OpenRTB still moves the auction. ARTF does not replace it. The framework lives inside the host, as a gRPC call that must fit in tmax (samples use 150ms). Delivery is a later hop.

The TV in the demo is a caption for the ticket. ARTF never reaches the player. VASTlint is the creative hop, a different tool.

3. What moves

The agent never returns a bid. It returns a list of patches. Each patch is independently acceptable: the host may apply a subset. Paths name business ids, not JSON array indexes.

Flags inside bid_request travel as protobuf booleans (secure: true). Spec JSON would want secure: 1. ARTF’s dialect is a fact, not a caller choice.

4. What it can write (v1.0 intents)

Eight named uses. New products are supposed to arrive as new intents, not as a free rewrite of the JSON. applicable_intents is how the host offers a subset for this call.

What the spec gives you

A container, a gRPC mutation API, named intents, and an orchestrator that may accept or reject each patch. Host keeps the data and the SLA.

What it does not

A check that the path exists in this auction, that the intent belongs on this lifecycle, or that BidRequest' is still legal OpenRTB. Fluent gRPC is not a valid auction.

Two plug-in seats

Host guardrail (the claim): orchestrator calls rtblint-grpc on openadtech.rtblint.v1 in band with the agent.

Agent self-check: MCP tools validate_artf_request / validate_artf_response so the agent can refuse to propose a set that would bounce.

Same engine, four doors

CLI --type artf-request / artf-response --apply. Library and WASM (validate_artf_*). MCP. gRPC. Verdicts match. The compose demo’s host and agent are stubs; the binary in the middle is not.

6. Where it stops, and what this is not

ARTF is

A container runtime + gRPC mutation API for work that has to happen inside an auction clock. Host keeps PII and the SLA. Vendor packages once. Intents are the product surface.

ARTF is not

A new bid object, a player, VAST delivery, or “the agent runs the exchange.” Fluent gRPC is not a valid auction.

A new bid object, a player, VAST delivery, or “the agent runs the exchange.” Fluent gRPC is not a valid auction. A badge of ARTF compliance is not something RTBlint claims.

RTBlint is

An OpenRTB linter that grew the three passes the framework left open. Independent implementation of their spec. Useful next to an agent, not as one.

The honest gap, one sentence

Nothing in the framework checks that the auction still validates once the mutations are applied, and a mutation is only meaningful relative to the request it targets.
