# Index and DV360 validation follows explicit integration directions

Reviewed 2026-10-09. Index supplier ingest and Index requests sent to DSPs have distinct required fields, extensions and timeout policies. Typed descriptors preserve unknown extensions. The DSP impression field `bcrid` remains optional because the current guide marks it temporarily unavailable. Banner formats require response dimensions only when the response is known to be a banner and the offered formats are usable. Fixed-size membership requires complete positive dimensions throughout the offer. Ratio, range and malformed references do not prove a fixed-size violation. Native and video responses to a multi-format impression do not inherit banner dimensions.

Index probability metrics stay between zero and one; session depth and unknown metrics retain their own units. Dynamic supplier pods signaled by a populated `poddur` require `podid` and `maxseq`. The seller guide leaves exchange-defined deal auction types open, while the DSP guide lists first-price and fixed-price types. This distinction applies to both the vendor rule and the catalog exception. Known SKAdNetwork offers constrain the returned network. Incomplete or malformed references defer membership checks. Advertiser pass-on exemptions and optional seat enablement require account context and remain advisory.

Sources: [Index supplier guide](https://kb.indexexchange.com/publishers/openrtb_integration/list_of_supported_openrtb_bid_request_fields_for_sellers.htm), [Index DSP guide](https://kb.indexexchange.com/dsps/open-rtb/list_of_supported_openrtb_bid_request_fields_dsp.htm), [Index response guide](https://kb.indexexchange.com/dsps/open-rtb/list_of_supported_openrtb_bid_response_fields_dsp.htm).

DV360 checks required device, user, inventory and publisher identifiers; typed vendor extensions; iOS bundle IDs; fixed-price deal floors; duplicate deal identifiers; and GMA dependencies. Explicit Native versions 1.0 and 1.1 are unsupported. An explicit sound-off-only playback offer must identify an outstream placement. Missing or zero placement does not satisfy this requirement. Modern `plcmt` takes precedence over legacy `placement`, including explicit zero. Mixed playback offers remain accepted because their selected behavior is unknown. Omitted playback methods retain the documented allowance for any method. Supply-chain exceptions, integration currency allowlists and guaranteed-deal enrollment require external account evidence.

Source: [DV360 OpenRTB specification](https://developers.google.com/display-video/ortb-spec).

The source fixture set contains 352 cases. The independent review adds 141 cases, including 100 positive controls, malformed-reference deferrals and default-profile isolation. Both generators reproduce the checked-in JSON exactly. The pair API validates the response and uses request references; it does not validate the request itself. Standalone request tests cover required fields and shapes separately.

The supplier profile additionally requires one consistent `podid` when a complete request contains multiple video impressions. Single non-podded videos remain valid without it. Malformed impression or video containers defer pod comparisons to standalone type checks. The [18 independent structured-pod controls](../../fixtures/exchange-depth/index-structured-pods/cases.json) and their [generator](index-structured-pod-generate.py) record the current seller guide's branch separately from the original field inventory.

Remaining gaps include account-dependent enablement, remote Native assets, verified creative rendering and authenticated exchange acceptance. These fixtures do not establish full exchange certification. Pinned source hashes appear in `index-dv360-sources.json`; verification receipts record commands and corpus hashes.
