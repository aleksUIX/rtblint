# PubMatic OpenWrap profiles validate the published custom wire and CTV endpoint

`pubmatic-openwrap` checks the custom OpenWrap request and response wire declarations. `pubmatic-openwrap-ctv` adds the selected legacy CTV endpoint's visible request conditions. The evidence is PubMatic's public OpenWrap fork at commit `24ff50ca1f00ca1e80ab80bcfa1c812c35f87797`, committed September 17, 2026. These profiles describe that middleware implementation. They do not claim coverage of PubMatic exchange acceptance rules, every OpenWrap endpoint, or a configured account's private settings.

The request inventory covers wrapper configuration, custom Prebid transparency and tracker fields, dynamic bidder maps, keyword arrays, deal-tier shapes, Google SDK parameters, SDK maps, placement wrappers, banner flex slots, video ad pods, privacy field types and OMID source fields. The response inventory covers summary arrays, video controls, prices and original currencies, ad-pod targeting maps, alternate aggregate ad-pod response keys, click trackers and SDK maps. Known nested containers and their items are checked recursively. Go booleans require JSON booleans. Integer declarations retain signed 64-bit, signed 32-bit and signed 8-bit bounds. Nulls remain accepted where `encoding/json` accepts them. Unknown future keys remain open. The [`models/request.go`](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/models/request.go), [`models/response.go`](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/models/response.go), and [custom SDK declarations](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/openrtb_ext/pubmatic_ow.go) establish those wire shapes.

CTV requests require at least one video impression. The middleware filters other impressions and removes other media objects from video impressions, so a mixed input is accepted. An explicit object in `imp.video.ext.adpod` is the visible configuration selected before the account's database configuration. After defaults, counts must be positive and ordered; durations must be positive and ordered; exclusion percentages must be within 0 and 100. Equal bounds are accepted. Zero or absent `minads` becomes 1 and zero or absent `maxads` becomes 3 in the executed code. The request model's max-count comment says 1, but the called default constant is 3. These conditions come from [`GetV25AdpodConfigs`, `setDefaultValues`, and `ValidateV25Configs`](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/adpod/adpod.go) and the [constants](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/models/adpod.go).

The CTV supply-chain helper requires version 1.0, a completeness flag, nonempty nodes, nonempty ASI/SID, SID of at most 64 Unicode characters, and `hp:1`. Its caller removes a failing chain and continues, so the profile emits `openrtb.profile.openwrap.schain_removed` as a warning. Generic OpenRTB errors still apply to malformed standard fields. The [endpoint helper](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/endpoints/legacy/ctv/video.go) and [before-validation hook](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/beforevalidationhook.go) establish both the conditions and this warning severity.

Raw OpenWrap requests do not compose the complete Prebid Server profile. Before-validation middleware injects and normalizes bidder configuration, targeting and account settings. Requiring normalized PBS bidder fields on that raw input would create false positives. Existing generic OpenRTB validation and pair consistency checks remain active. A custom response-duration or bid-count cap is not added: the [production ad-pod middleware](https://github.com/PubMatic-OpenWrap/prebid-server/blob/24ff50ca1f00ca1e80ab80bcfa1c812c35f87797/modules/pubmatic/openwrap/middleware/adpod/openrtb.go) can generate aggregate responses, which do not prove such a cap on every returned bid.

Explicit gaps remain:

- Account-derived profile IDs, placement configuration, tag IDs, consent policy, timeout policy, cached ad-pod settings and ad-server creative durations need runtime context. Their absence does not prove a malformed raw request.
- The current ad-pod resolver does not use the global request ad-pod argument. Global fields are typed, but unused older pointer validators and duration-product conditions are not imposed.
- Imported generic PBS containers in `imp.ext.data`, `imp.ext.prebid` and `bid.ext.prebid` do not receive complete semantic coverage here. The custom profile treats raw SKAdNetwork and client configuration blobs as opaque. Generic OpenRTB extension validation, including SKAdNetwork checks, remains active.
- Device extension helpers delete incorrectly typed optional identifiers. The profile does not turn their tolerant runtime behavior into acceptance errors.
- Only canonical published JSON field names and the published response debug capitalization variants are inspected. Go's case-insensitive struct-field aliases are outside this inventory.
- Imported deal-tier fields are typed. Comments describe a nonempty prefix and positive minimum, but full normalization and downstream targeting configuration are outside this selected wire stage.

[`pubmatic-openwrap-field-inventory.json`](pubmatic-openwrap-field-inventory.json) records the custom paths and types. [`pubmatic-openwrap-sources.json`](pubmatic-openwrap-sources.json) records exact source URLs and SHA-256 bytes, excluding failed retrievals. [`pubmatic-openwrap-case-generate.py`](pubmatic-openwrap-case-generate.py) regenerates independent source-declaration fixtures, including positive values, type mutations, null controls, integer-width boundaries, unknown contexts, CTV defaults and response variants.
