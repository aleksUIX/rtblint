# Final source controls cover Unity deals and Vungle producer extensions.

Unity's current [Bid response table](https://docs.unity.com/en-us/grow/programmatic/unity-exchange/bid-responses) makes `dealid` optional and requires a selected ID to match a request deal ID. The paired rule resolves the impression uniquely, then compares only an explicit deal array whose every entry has a unique, nonempty string ID. Missing arrays, malformed entries and duplicate identifiers leave the offer unknown. An explicit empty array establishes that no deal was offered. Malformed supplied media containers also defer placement and paired banner-dimension inference. Explicit response creative types retain their independent requirements. Standalone request validation remains responsible for malformed reference fields.

Vungle's current [OpenRTB 2.5 guide](https://support.vungle.com/hc/en-us/articles/360045953431-Vungle-Exchange-OpenRTB-2-5-Integration-Guide), sections 3.2.2 through 3.2.2.2, documents `source.ext.schain` and all its listed members as optional. Supplied objects, arrays, strings and integer flags receive type and flag-bound checks. Unknown members remain open. This producer validation does not establish seller authorization, chain completeness, payment routing or identity accuracy.

Section 3.2.3 makes the extension object conditional on the optional `regs` object being supplied. The container must be an object. GDPR and US privacy members remain optional. An empty object introduces no mandatory privacy child. Section 2.3's consumer guidance distinguishes presence guarantees from downstream handling of optional values.
