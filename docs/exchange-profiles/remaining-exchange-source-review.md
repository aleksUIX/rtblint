# Remaining exchange contracts need substantive current source evidence

The October 9, 2026 primary-source review recovered a substantive current PubMatic OpenWrap implementation and added `pubmatic-openwrap` and `pubmatic-openwrap-ctv`. The selected scopes and gaps are recorded in [`pubmatic-openwrap-depth.md`](pubmatic-openwrap-depth.md). PubMatic's full exchange contract remains separate: the [official support portal](https://help.pubmatic.com/) requires login for its detailed partner documentation. A generic OpenRTB fork or the public 2021 efficiency guidance does not prove a complete current exchange acceptance contract.

OpenX's [official portal](https://docs.openx.com/) exposes navigation to supplier and buyer protocol tables. The direct routes include supplier bid requests and responses, OpenRTB parameters and ad pods, plus buyer bid requests, responses, and each child object. Direct GET requests to 35 of these current protocol routes followed an OAuth/login redirect and returned a 1,381-byte application shell. The tables themselves were not retrieved. Search did not recover substantive current primary table content. The outcome is a deferred buyer and supplier contract pending access to those documented current tables. The navigation is evidence that the tables exist; it is not an acceptance-rule oracle.

Yahoo's [current ConnectID server-to-server integration guide](https://help.yahooinc.com/connect-id/docs/integrate-with-connectid-server-to-server-method) provides a focused identity contract, including the OpenRTB 2.5 extension path, OpenRTB 2.6 standard path, the Yahoo identity source and the UID type. That material does not supply a complete exchange bid-request and bid-response contract. A full Yahoo exchange profile remains deferred pending the direct exchange protocol documentation.

Moloco's [official support center](https://help.moloco.com/hc/en-us) exposes campaign, measurement and integration guides, and its [brand safety policy](https://www.moloco.com/terms-and-policies/brand-safety-policy) describes app-ads.txt policy. The targeted current primary-source search did not retrieve a substantive Moloco exchange OpenRTB request and response contract. This is an evidence gap, not a claim that Moloco has no specification.

FreeWheel's outcome remains the documented [source-access deferral](freewheel-source-review.md). Its cached producer request table and configurable version/account behavior do not establish a complete current acceptance profile. Public resource navigation names the integration guides, but their substantive current contents were not retrieved.
